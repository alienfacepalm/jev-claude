# Golden cases

Generated by `node conformance/generate.mjs` (Node.js 24.21) from the Node implementation itself;
never edit these files by hand. Each file is a JSON array of `{ "name", "input", "expected" }`.
Every `expected` is what the real Node function returned for that `input` (SPEC.md 16.2). A port
that believes a case is wrong reports it rather than editing it.

Regenerating is deterministic: running the generator twice leaves `git status conformance/cases`
unchanged.

## Tagged encoding

Plain JSON cannot hold some JavaScript values, so the files use these tags. A tag is a JSON object
with exactly one key, and that key is one of the names below; no real input or output has that
shape (the generator refuses to write one). Decode tags anywhere in `input` and `expected`, at any
depth, before calling or comparing.

| Tag | Meaning |
| --- | --- |
| `{"$undefined": true}` | JavaScript `undefined`. As an object member it means the key is present with the value `undefined` (JavaScript treats that like an absent key almost everywhere; `JSON.stringify` omits it). As an array element it is an `undefined` element. As a whole `expected` it means the function returned `undefined`. |
| `{"$number": "NaN"}`, `{"$number": "Infinity"}`, `{"$number": "-Infinity"}`, `{"$number": "-0"}` | Those IEEE-754 doubles. Every other number is written as plain JSON and is a double. |
| `{"$utf16": [55296, 97]}` | A string containing a lone surrogate, given as its UTF-16 code units. Strings without lone surrogates are plain JSON strings. |
| `{"$hex": "7b7d"}` | Raw bytes, hex encoded (lower case). Used for `parse` inputs, which are bytes that may not be valid UTF-8. |
| `{"$throws": true}` | Only in `expected`: the Node call threw. The port's call must fail (raise, return an error); the message is free-form. |
| `{"$clock": true}` | Only in `write-decision` `expected`: an `at` that `markManual` took from the clock (SPEC 16.2). It matches any number in the port's output. |

Object key order in these files is JavaScript's own order (SPEC 3.3): canonical array-index keys
first in ascending order, then insertion order. Ports compare objects with that order unless the
row below says "compare as a map".

### Running the status-line cases

For each case: make an empty status directory and an empty working directory, write the files the
input names into the status directory, then run the program with that working directory and an
environment holding `JEV_STATUS_DIR` (the status directory), `JEV_ICONS` (from `icons`), and
`HOME`, `USERPROFILE`, `TEMP`, `TMP`, `TMPDIR` pointed at a scratch directory, with no other
`JEV_*`, `TYPESAFE_*`, `ANTHROPIC_*`, or `CLAUDE_*` variable. Write `stdin`, close it, and compare
stdout byte for byte. The program must exit 0 with nothing on stderr.

The status line reads the real clock to decide which sub-agents are fresh, so the data fixes that
instead of an injected `now`: fresh entries carry `at` = 4102444800000 (2100-01-01), stale ones `0`
or no `at`. Every `workspace.current_dir` either names a directory that does not exist (so the git
branch lookup fails) or comes with `worktree.branch`, so no case depends on a real repository.
